# Project Main Log

High-level record of completed tasks: new classes and their main functionality, plus design and architectural choices made.

1. **ClaudeProjectLog setup** — contains communication and choices with Claude.
2. **Git repo setup** — for version control and deliverables. Private GitHub remote (`groatse/DISMultiplayerTank`), UE5 `.gitignore`, Git LFS for binary assets, and a `/sync` skill that pulls/commits/pushes only on explicit command.
3. **Game design defined** — top-down Atari Combat-style 2-player tank battle over DIS (GRILL DIS plugin, UE 5.7). Key architectural choices: standard DIS authority split (each instance owns its tank and shells; shooter publishes Fire/Detonation, victim adjudicates damage on itself); shells are full DIS entities publishing Entity State PDUs because they are steerable in flight like the original; instance identity is auto-negotiated on the network (zero-click game start) with a failsafe against race conditions; one shell at a time per tank; walls; classic respawn (freeze + forced move in random direction); score display with map reset at 10 kills.
4. **Phase 1: local gameplay core** — new classes: `ATankDISTanks` (fixed-timestep Combat movement, swept wall collision, placeholder cube visuals), `AArenaDISTanks` (procedural floor/walls/obstacles/light/top-down camera/spawn slots — no map asset), `APlayerControllerDISTanks` (code-built Enhanced Input, zero content assets), `AGameModeDISTanks` (arena spawn, pawn spawn at slot, camera view target). Architectural choices: procedural arena on the engine Entry map instead of a binary .umap (keeps content diffable/reviewable); fixed 60 Hz movement substep for frame-rate-independent, DR-friendly simulation; runtime-constructed input so the whole project stays C++-only.
5. **Phase 2: shell & death sequence** — new class `AShellDISTanks` (fixed-timestep kinematic shell, steers in flight with the owner tank's turn input, swept impact detection, ignores shooter and other shells, failsafe lifetime). `ATankDISTanks` gained firing (one shell at a time via weak pointer), hit handling, and the classic Combat death sequence (control freeze + forced random-direction slide, invulnerable while dying). Temporary practice-target tank for local hit testing. New `LogDISTanks` category with structured markers (Fire/ShellImpact/TankDeath/TankRespawned) feeding the future test harness. Verified by user playtest.
6. **Phase 3: DIS tank synchronization** — new classes: `UPDURouterDISTanks` (sole GRILL DIS touchpoint: UDP broadcast + shared-port loopback receive sockets, threshold/heartbeat ESPDU publishing that mirrors the receivers' dead-reckoning prediction, ghost spawning/routing with out-of-order drop and 10 s timeout) and `PDUTypesDISTanks.h` (protocol conventions). `ATankDISTanks` gained ghost mode (constant-velocity DR + capped extrapolation + smoothing). Architectural choices: bypassed the plugin's DISGameManager/components (their receive routing needs a content asset) in favor of the raw UDP+PDU subsystem layers; arena-local meters ride in the ECEF fields on both peers instead of true geodesy (documented simplification); error-bounded sending — a straight-driving tank costs one heartbeat per second, corrections go out the moment reality drifts >0.1 m/2° from the mirrored prediction. Verified: two localhost instances each ghost the other (log markers + visual).
7. **Phase 4: DIS shell entity & kill flow** — shells are full DIS entities: Fire PDU + 10 Hz threshold-triggered ESPDUs (steering corrections go out within a frame), ghost shells seeded from the Fire PDU with collision disabled (visual-only), removed on Detonation or 2 s silence. Kill flow uses the standard DIS authority split: shooter's exact shell vs dead-reckoned victim → Detonation PDU; victim validates (tolerance 250 cm, not already dying) before dying and publishing Damage=Destroyed, which the remote ghost mirrors (darkened tint via new dynamic-material infrastructure). Publish logic unified in `FPublishTrackerDISTanks`. Gameplay classes remain DIS-type-free; the router owns all identity mapping.
8. **Phase 5: peer negotiation & zero-click auto-start** — new class `UPeerRegistryDISTanks`: random session token doubles as the DIS application ID; slots derived by sorting all known tokens (deterministic everywhere, no handshake, race-free). GameMode match flow: spawn frozen → "waiting for peers" → on first contact reposition to negotiated slot, apply Combat colors (green/red), unfreeze — launch two instances anywhere on the network and the match just starts. Ghost tanks re-tint on peer-set changes and snap across large corrections. Death sequence upgraded: bounce away from the killer in a 120° arc with random spin. Fixed engine-cube material gotcha (default slot is parameterless WorldGridMaterial; assigned BasicShapeMaterial for tinting).
9. **N-player spawning & tinting** — eight slot-indexed perimeter spawns with computed face-toward-center rotations (wrapping past the count); colors are the classic four then golden-angle HSV hues for any N; shells tinted by their owner's slot for attribution. Verified live with three instances: deterministic slots 0/1/2 on all machines (including mid-negotiation re-slotting) and identical green/red/blue scenes everywhere.
10. **Phase 6: score & round flow** — new class `AHUDDISTanks` (Canvas score row colored by slot, round number, waiting banner; no content assets). Score state rides the tank ESPDU as DIS articulation records (type 0 = round number, type = killer app → deaths); victim-owned attribution with take-max merge makes counters immune to packet loss/reorder; score changes force immediate publish. The 10-kill map reset needs no reset message: all instances watch identical counters, the round number in published state is the convergence mechanism, and each instance repositions only its own tank (death sequences aborted on reset).
11. **Phase 7: semi-automated network test harness** — new classes: `FNetConditionerDISTanks` (seeded inbound loss/latency/jitter/duplication on all consumed PDUs via `-NetSim*` args, inert by default; jitter doubles as reordering) and `UAutoPilotDISTanks` (seeded unattended driver via `-AutoPilot`, steers through shots). `Tools/RunNetTest.ps1` runs two autopilot instances per lag profile (Baseline/Latency/Loss/Nasty) and asserts from structured logs: match start, no fatal errors, cross-instance score-view convergence, bounded dead-reckoning error (new `ScoreView` marker + DR stats in `RouterHealth`). Validated live: Baseline PASS (DR mean ≤23 cm) and Nasty PASS (250 ms ±100 + 30 % loss + dupes: kills adjudicated, scores converged, worst DR correction 257 cm ≈ latency × speed — confirming the bounded-error design).
